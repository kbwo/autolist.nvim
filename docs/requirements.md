# リスト自動整形プラグイン 要件定義（ドラフト）

この文書は単独で読めるように書く。既存プラグインのソースを前提にした記述はしない。

## 1. 目的

markdown のようなプレーンテキストを書いているとき、リストの体裁（マーカー・連番・インデント・チェックボックス）の維持を手作業でやらなくて済むようにする。
書き手は中身に集中し、整合はエディタ側が保つ。

## 2. スコープ

- **対象**: リスト行の入力補助と整形。markdown を第一級とし、他の filetype は設定で追加できる。
- **対象外**: プレビューやレンダリング、表の整形、テキストの折り返し、見出しや脚注など、リスト以外の markdown 要素。

## 3. 用語

この文書で使う言葉を先に固定する。

| 用語 | 意味 | 例 |
| --- | --- | --- |
| マーカー | 行頭でリスト項目であることを示す記号 | `-` `*` `+` `1.` `2)` `a)` `IV.` |
| 順序なしリスト | 連番を持たないマーカーのリスト | `- りんご` |
| 順序付きリスト | 連番を持つマーカーのリスト | `1. りんご` |
| 項目 | マーカー 1 個とその内容からなる 1 単位 | `1. りんご` |
| 内容 | マーカーと、その直後の空白を除いた残り | `りんご` |
| 空項目 | 内容が空の項目 | `- ` |
| インデント階層 | 行頭の空白量で決まる入れ子の深さ | 下の例の「子」 |
| 兄弟 | 同じ階層で連続する項目同士 | 下の例の `1.` と `2.` |
| リストブロック | ひとまとまりとして扱う項目の連なり | 下の例の 4 行全体 |
| チェックボックス | マーカー直後に置く `[ ]` / `[x]` | `- [x] 済み` |

```markdown
1. 親
    - 子
    - 子
2. 親
```

## 4. 機能要件

各要件は「入力（`|` はカーソル位置）→ 操作 → 出力」の形で受け入れ条件を書く。

### FR-1 改行したときにリストを続ける

リスト項目の行で改行したら、次の行にも同じ種類のマーカーを置く。順序付きなら番号を 1 つ進める。

```markdown
- りんご|          →  改行  →   - りんご
                                - |
1. りんご|         →  改行  →   1. りんご
                                2. |
    a) りんご|     →  改行  →       a) りんご
                                    b) |
```

- インデント量は元の行と揃える。
- マーカーの区切り記号（`.` と `)`）は元の行のものを保つ。
- チェックボックス付きの項目から続けた場合は、チェックボックスを引き継ぎ、**未チェック**で作る。

```markdown
- [x] 済み|        →  改行  →   - [x] 済み
                                - [ ] |
```

### FR-2 空項目で改行したらリストを抜ける

空項目のまま改行したら、その空項目を消して通常の行に戻る。リストを終えるのに「行頭を消す」手作業を要らなくするための挙動。

```markdown
- りんご                        - りんご
- |                →  改行  →   |
```

### FR-3 順序付きリストの連番を振り直す

項目の削除・並べ替え・インデント変更のあとに、連番を通し番号として正しい状態に戻す。

```markdown
1. あ                           1. あ
5. い             →  再計算  →  2. い
2. う                           3. う
```

- 入れ子は階層ごとに独立して数える。親の番号は子に影響しない。
- 順序なしリストは変更しない。
- アルファベット（`a) b) c)`）とローマ数字（`I. II. III.`）も連番として扱う。

```markdown
1. 親                           1. 親
    5. 子           →  再計算  →     1. 子
    9. 子                           2. 子
3. 親                           2. 親
```

### FR-4 インデントの上げ下げに追随する

項目のインデントを変えたら、変更後の階層に合った連番・マーカーになる。

```markdown
1. あ                           1. あ
2. い             →  い を1段下げ  →      1. い
```

### FR-5 チェックボックスを切り替える

チェックボックスを持つ項目の上で、`[ ]` と `[x]` を切り替える。

### FR-6 マーカーの種類を変換する

リストブロックのマーカー種別を、あらかじめ決めた順番（例: `-` → `*` → `1.` → `1)` → `a)` → `I.` → `-` …）で切り替える。
順序付きに変えたときは、そのブロック全体が正しい連番になる。

```markdown
- あ                            1. あ
- い              →  変換  →    2. い
- う                            3. う
```

### FR-7 リストとして扱わない文脈を除外する

見た目がリストに似ていても、リストではない箇所では何もしない。少なくとも次を区別する。

- コードブロックの中（``` で囲まれた範囲、インデントコードブロック）
- 強調記法。`*bold*` の `*` をマーカーと誤認しない
- 区切り線 `---` や `***`
- 文中に現れる `1.`（行頭でないもの）

### FR-8 リスト以外の行では邪魔をしない

リストでない行では、キーは本来の動作のままにする。改行は改行、タブはタブ。

## 5. 非機能要件

- **NFR-1 応答性**: 1 回の操作でカーソルが目に見えて待たされないこと。大きなファイルでも編集のたびにバッファ全体を走査しない。
- **NFR-2 共存**: 他プラグインが `<CR>` や `<Tab>` に割り当てている機能を壊さない。読み込み順に依存して壊れる設計にしない。
- **NFR-3 undo**: 1 回の操作は 1 回の undo で元に戻る。自動整形の結果だけが取り残されない。
- **NFR-4 既定値で動く**: 設定を書かなくても markdown で妥当に動く。設定は上書きのためにある。
- **NFR-5 テスト可能**: すべての機能要件を、実際のバッファに対する自動テストとして書ける形にする。受け入れ条件は本書の入出力例をそのまま使う。
- **NFR-6 予測可能性**: 書き手が明示的に操作していない行を勝手に書き換えない。整形の影響範囲が説明できること。
