# リスト自動整形プラグイン 要件定義

この文書は単独で読めるように書く。他の資料を参照しないと意味が通らない記述はしない。

## 1. 目的

markdown のようなプレーンテキストを書いているとき、リストの体裁（マーカー・連番・インデント・チェックボックス）の維持を手作業でやらなくて済むようにする。
書き手は中身に集中し、整合はエディタ側が保つ。

## 2. スコープ

- **対象**: リスト行の入力補助と整形。最初に作る版は markdown だけを対象にし、挙動を詰める。他の filetype（text, tex, norg など）は、あとから設定で足せる形にしておく。
- **対象外**: プレビューやレンダリング、表の整形、テキストの折り返し、見出しや脚注など、リスト以外の markdown 要素。

## 3. 用語

この文書で使う言葉を先に固定する。

| 用語 | 意味 | 例 |
| --- | --- | --- |
| マーカー | 行頭でリスト項目であることを示す記号 | `-` `*` `+` `1.` `2)` `a)` `IV.` |
| 順序なしリスト | 連番を持たないマーカーのリスト | `- りんご` |
| 順序付きリスト | 連番を持つマーカーのリスト | `1. りんご` |
| 項目 | マーカー 1 個とその内容からなる 1 単位 | `1. りんご` |
| 内容 | マーカーと、その直後の空白を除いた残り | `りんご` |
| 空項目 | 内容が空の項目。チェックボックスだけがあって内容が空のものも含む | `- ` `- [ ] ` |
| インデント階層 | 行頭の空白量で決まる入れ子の深さ | 下の例の「子」 |
| 兄弟 | 同じ階層で連続する項目同士 | 下の例の `1.` と `2.` |
| リストブロック | ひとまとまりとして扱う項目の連なり。境界は共通ルールで定義する | 下の例の 5 行全体 |
| 継続行 | マーカーを持たないが、直前の項目より深くインデントされている行。その項目の内容の続き | 下の例の `2 行目` |
| チェックボックス | マーカー直後に置く `[ ]` / `[x]` | `- [x] 済み` |

```markdown
1. 親
    - 子
      2 行目
    - 子
2. 親
```

## 4. 機能要件

各要件は「入力（`|` はカーソル位置）→ 操作 → 出力」の形で受け入れ条件を書く。

### 共通ルール

- **入れ子の判定はインデントの深さの相対比較で行う。** ある項目より行頭の空白が多ければ、その項目の子とする。何スペース深いかは問わない。2 スペースと 4 スペースが混在する文書でも、タブと空白が混ざる文書でも、階層関係が壊れないようにするため。
- **リストブロックは、空行または「継続行でない非リスト行」で区切られる。** 空行を挟んだ項目は別のリストとして扱い、連番は改めて 1 から数える。

```markdown
1. あ
2. い

1. う      ← 空行を挟んだので、ここから別のリスト
```

- **継続行はブロックを分断しない。** マーカーがなくても、直前の項目より深くインデントされている行は、その項目の内容の続きとみなしてブロックに含める。下の例は 3 行で 1 つのブロックであり、再計算はこれをまたいで働く。

```markdown
1. あ
   内容の 2 行目      ← 継続行。ここでブロックは切れない
2. い
```

- **引用ブロックの中のリストも同じように扱う。** 行頭の `>` は、行頭の空白と同じくリスト項目の前置きとみなす。継続・連番の振り直し・マーカーの変換は、引用記号をそのまま保ったまま行う。

```markdown
> - りんご|        →  改行  →   > - りんご
                                > - |
```

### FR-1 改行したときにリストを続ける

リスト項目の行で改行したら、次の行にも同じ種類のマーカーを置く。順序付きなら番号を 1 つ進める。

```markdown
- りんご|          →  改行  →   - りんご
                                - |
1. りんご|         →  改行  →   1. りんご
                                2. |
    a) りんご|     →  改行  →       a) りんご
                                    b) |
```

- インデント量は元の行と揃える。
- マーカーの区切り記号（`.` と `)`）は元の行のものを保つ。
- チェックボックス付きの項目から続けた場合は、チェックボックスを引き継ぎ、**未チェック**で作る。チェック済みかどうかに関係なく、新しい項目は常に未チェックで始まる。

```markdown
- [x] 済み|        →  改行  →   - [x] 済み
                                - [ ] |
- [ ] 未|          →  改行  →   - [ ] 未
                                - [ ] |
```

行の途中で改行した場合は、カーソル以降の文字列を新しい項目の内容にする。

```markdown
- りんご|ばなな    →  改行  →   - りんご
                                - |ばなな
```

**継続行では継続しない。** 内容が長くて 2 行目以降をマーカーなしで書いた場合、その行の末尾で改行してもマーカーは出さない。ただの改行になる。（継続行はブロックには含まれるが、新しい項目を作る起点にはしない）

```markdown
- りんご。説明が長いので        - りんご。説明が長いので
  2 行目に続いている|  →  改行  →   2 行目に続いている
                                |
```

**全項目が同じ数字で書かれているリストでは、同じ数字を置く。**（FR-3 の「全部 `1.`」の書き方を、入力中も保つ）

```markdown
1. あ                           1. あ
1. い|             →  改行  →   1. い
                                1. |
```

### FR-2 空項目で改行したらリストを抜ける

空項目のまま改行したら、その空項目を消して通常の行に戻る。リストを終えるのに「行頭を消す」手作業を要らなくするための挙動。

```markdown
- りんご                        - りんご
- |                →  改行  →   |

- [ ] りんご                    - [ ] りんご
- [ ] |            →  改行  →   |
```

チェックボックス付きの空項目も同じく空項目なので、そこで改行したら行ごと消えて通常の行に戻る。

### FR-3 順序付きリストの連番を振り直す

項目の削除・並べ替え・インデント変更のあとに、連番を通し番号として正しい状態に戻す。
**振り直しは利用者が明示的に指示したときだけ走る。** 編集を監視して自動で書き換えることはしない。書き手が触っていない行が知らないうちに変わるのを避け、いつ何が起きるかを説明できる状態に保つため。

```markdown
1. あ                           1. あ
5. い             →  再計算  →  2. い
2. う                           3. う
```

- **対象はカーソルのあるリストブロック全体**。その中の入れ子もまとめて整える。ブロックの外には手を出さない。
- 行数の上限は設けない。どこまで直すかはブロックの境界だけで決まる。長いリストの途中から番号が揃わなくなる、ということが起きないようにするため。
- 入れ子は階層ごとに独立して数える。親の番号は子に影響しない。
- 順序なしリストは変更しない。
- アルファベット（`a) b) c)`）とローマ数字（`I. II. III.`）も連番として扱う。

```markdown
1. 親                           1. 親
    5. 子           →  再計算  →     5. 子
    9. 子                           6. 子
3. 親                           2. 親
```

**起点はその階層の先頭項目の数字を尊重する。** 1 に矯正しない。`3.` から始めたリストは `3. 4. 5.` になる。
（例外は、インデント操作で階層が新しくできた場合。FR-4 のとおり 1 から始める）

```markdown
3. あ                           3. あ
7. い             →  再計算  →  4. い
9. う                           5. う
```

**すべての項目が同じ数字で書かれている場合は、その書き方を維持する。** markdown では番号を全部 `1.` のまま書いても表示は連番になるため、この書き方を意図的に使う人がいる。振り直しの対象外とし、勝手に `1. 2. 3.` へ直さない。

```markdown
1. あ                           1. あ
1. い             →  再計算  →  1. い      ← 変更しない
1. う                           1. う
```

### FR-4 インデントの上げ下げに追随する

プラグインが提供するインデント操作で項目の階層を変えたら、その操作の中で連番を整える。
FR-3 を別途呼ばなくてよい。利用者の明示的な操作なので、自動整形にはあたらない。

下げた先に既に兄弟がいる場合は、その並びの続きの番号になる。

```markdown
1. あ                                    1. あ
    1. か     →  「い」を1段下げる  →         1. か
2. い                                        2. い
3. う                                    2. う
```

下げた先に兄弟がいない場合、つまりその項目が新しい階層の唯一の項目になる場合は、1 から数え直す。

```markdown
1. あ                                    1. あ
2. い          →  「い」を1段下げる  →         1. い
3. う                                    2. う
```

### FR-5 チェックボックスを切り替える

チェックボックスを持つ項目の上で、`[ ]` と `[x]` を切り替える。

### FR-6 マーカーの種類を変換する

マーカー種別を、あらかじめ決めた順番で切り替える。
順序付きに変えたときは、対象が正しい連番になる。

```markdown
- あ                            1. あ
- い              →  変換  →    2. い
- う                            3. う
```

**並び順の各項目は「マーカー」と「チェックボックスを持つかどうか」の組。**
チェックボックスの有無もマーカー種別の一部として切り替える。既定の順番は `-` → `- [ ]` → `*` → `1.` → `1)` → `a)` → `I.` → `-` …。

```markdown
- 買い物                        - [ ] 買い物
- 洗濯            →  変換  →    - [ ] 洗濯
```

- **変換先がチェックボックスを持つ場合**、持っていない項目には未チェックで付ける。既に持っている項目のチェック状態はそのまま保つ。作業の済み・未済は書き手の記録であって、見た目の変換で消してよいものではないため。
- **変換先がチェックボックスを持たない場合**、チェックボックスを外す。並び順を一周したときに元の姿へ戻れるようにするため。

**並び順は前後どちらにも回せる。** 行き過ぎたときに戻れるようにするため。端に来たら反対の端へ回り込む。

**対象範囲は 2 通りあり、利用者がどちらかを選ぶ。**

- **ブロック全体**: そのブロックの入れ子をすべて含めて変換する。順序付きになった場合、連番は階層ごとに 1 から数える。
- **兄弟の並びだけ**: カーソルのある項目と同じ階層の、連続した兄弟だけを変換する。その親と子には触れない。

範囲を 2 つに分けるのは、入れ子のリストでは階層ごとにマーカーを変えたいことがあるため。下の例は、子の階層だけを変換したもの。

```markdown
- 親                            - 親
    - 子              →  変換  →     1. 子
    - 子                            2. 子
- 親                            - 親
```

### FR-7 リストとして扱わない文脈を除外する

見た目がリストに似ていても、リストではない箇所では何もしない。少なくとも次を区別する。

- コードブロックの中（``` で囲まれた範囲、インデントコードブロック）
- 強調記法。`*bold*` の `*` をマーカーと誤認しない
- 区切り線 `---` や `***`
- 文中に現れる `1.`（行頭でないもの）

### FR-8 リスト以外の行では邪魔をしない

リストでない行では、キーは本来の動作のままにする。改行は改行、タブはタブ。

### FR-9 リストでない行をリストにする

マーカーを持たない平文の行に、マーカーを付けてリスト項目にする。
字下げだけで階層を書いたメモを、あとから markdown のリストに直すための機能。下のような書き方は珍しくない。

```
ccmanager                      - ccmanager
	設定用のskillを用意   →  変換  →   	- 設定用のskillを用意
	worktreeを消せるように             	- worktreeを消せるように
```

- **対象は利用者が指定した行の範囲。** 既定はカーソル行 1 行。ブロックの範囲を推測しない。平文には空行のないメモのような書き方もあり、どこまでが一続きかを機械が決めると、意図の何倍もの行を書き換えてしまうため。
- **元の字下げはそのまま残し、その後ろにマーカーを差し込む。** 字下げが既に階層を表しているので、共通ルールの相対比較がそのまま働く。字下げを作り直さないのは、タブと空白のどちらで書かれていても壊さないため。
- **使うマーカーは、FR-6 の並び順の先頭。** 変換用に別の設定を増やさない。ほかの種別にしたいときは、変換してから FR-6 を使う。
- **範囲内でも、次の行は変更しない。** 既にマーカーを持つ行、空行、コードブロックの中の行、区切り線。
- **引用記号は保つ。** 共通ルールのとおり、引用の中でも同じように働く。
- 先頭が順序付きのマーカーに設定されている場合は、範囲の中で階層ごとに 1 から数える。

## 5. 非機能要件

- **NFR-1 応答性**: 1 回の操作でカーソルが目に見えて待たされないこと。大きなファイルでも編集のたびにバッファ全体を走査しない。
- **NFR-2 共存**: 他プラグインが `<CR>` や `<Tab>` に割り当てている機能を壊さない。読み込み順に依存して壊れる設計にしない。
- **NFR-3 undo**: 1 回の操作は 1 回の undo で元に戻る。自動整形の結果だけが取り残されない。
- **NFR-4 既定値で動く**: 設定を書かなくても markdown で妥当に動く。設定は上書きのためにある。
- **NFR-5 テスト可能**: すべての機能要件を、実際のバッファに対する自動テストとして書ける形にする。受け入れ条件は本書の入出力例をそのまま使う。
- **NFR-6 予測可能性**: 書き手が明示的に操作していない行を勝手に書き換えない。整形の影響範囲が説明できること。
- **NFR-7 キーマップを奪わない**: プラグイン側ではキーマップを一切定義しない。機能はコマンドと関数として公開し、どのキーに割り当てるかは利用者が決める。既に使っているキーの動作を勝手に変えないため。

## 6. 実装で決めた細部

4 章・5 章を実装するには足りない粒度の判断を、確定した内容としてここに書く。
4 章に書いてあることの言い換えはしない。ここにあるのは、4 章だけでは動作が一意に決まらなかった点だけ。

### 6-1 マーカーの読み取り

- **アルファベットのマーカーは同じ大小の英字の連なりとする。** `ab)` は 28 番目として扱う。`Ab)` のように大小が混ざったものはマーカーとみなさない。
- **1 文字のマーカーはローマ数字とアルファベットの区別がつかない。** `i.` は「アルファベットの 9 番目」とも「ローマ数字の 1」とも読める。次の順で決める。
  1. 同じ兄弟の並びに、読み方が一意に決まる項目（`ii.` のような 2 文字以上のローマ数字、`b.` のようなローマ数字にならない文字）があれば、それに合わせる。
  2. なければ大小で決める。大文字（`I.` `V.`）はローマ数字、小文字（`i.` `v.`）はアルファベット。
- **2 文字以上でも、正規のローマ数字の書き方になっていないものはアルファベットとして扱う。** `iix.` はローマ数字の書き方として正しくない（8 は `viii`）ので、アルファベットの連なりとして数える。

### 6-2 引用ブロック

- **引用の深さが違う行はリストブロックを分ける。** `> - あ` と `> > - い` は別のブロック。深さの違う引用は別の入れ物なので、連番を通して数えない。
- **FR-2 で引用の中の空項目を消したときは、引用記号を残す。** `> - |` で改行したら `> |` になる。空項目を消すのはリストを抜けるためであって、引用を抜けるためではない。

### 6-3 改行（FR-1 / FR-2）

- **カーソルがマーカーより手前にあるときは、通常の改行にする。** `|- りんご` のように行頭にいる状態は、項目に書き足している途中ではないため。マーカーの直後（`- |`）から後ろは FR-1 / FR-2 の対象。

### 6-4 連番の振り直し（FR-3）

- **「全部同じ数字」の判定は兄弟の並びごとに、順序付きの項目が 2 つ以上あるときだけ行う。** 1 つしかない並びは比較のしようがないので、通常どおり振り直す。
- **1 つの並びにマーカーの種別が混ざっている場合は、各項目の種別と区切り記号をそのままに、順番だけを通す。** `1. / 5) / 9.` は `1. / 2) / 3.` になる。種別を揃えるのは FR-6 の仕事で、FR-3 は番号しか触らない。
- **順序なしの項目は数に入れない。** 順序付きと順序なしが混ざった並びでは、順序付きの項目どうしで数える。

### 6-5 インデント操作（FR-4）

- **その項目の継続行と子孫をまとめて動かす。** 項目だけ動かすと入れ子が壊れるため。
- **下げ幅は、直前の兄弟が既に持っている子の深さに合わせる。子がなければ 'shiftwidth' の分だけ深くする。** 文書内で使われている幅に合わせるほうが、設定値を押しつけるより壊さない。
- **その階層の先頭項目は下げられない。** 入れ子にする先の親がないため、何もしない。
- **上げ幅は親の階層に合わせる。** 最上位の項目は上げられない。

### 6-6 チェックボックス（FR-5）

- **チェックボックスのない項目では何もしない。** 勝手に付け足さない。FR-5 は切り替えの要件であって、付与の要件ではない。

### 6-7 マーカーの変換（FR-6）

- **今の種別は、対象の先頭項目から見る。** ブロック全体ならブロックの先頭項目、兄弟の並びだけならその並びの先頭項目。並びの中で種別が混ざっている場合も、先頭に合わせて全部を次の種別に揃える。
- **先頭項目の種別が並び順のどこにも無い場合は、回す向きによらず並び順の先頭に変換する。** 設定にない書き方から始めても、必ず並びに乗るようにするため。
- **FR-3 の「全部同じ数字は維持する」はここでは適用しない。** 種別の変換は利用者の明示操作で、そのとき番号を作り直すのは操作の一部だから。
- なお 4 章の FR-6 の例（`-` から `1.` へ）は、既定の並び順では 3 回分の操作にあたる。

### 6-8 リストでない文脈（FR-7）

- **インデントコードブロックは「空行のあとに 4 桁以上の字下げがあり、かつリストの途中でない行」とする。** リストの途中の深い字下げは継続行や入れ子であってコードではない、という区別を優先する。
- **ファイルの先頭の字下げはコードブロックの開始とみなさない。** markdown の仕様上はコードブロックだが、深い階層のリストだけを書いたファイルや切り出した断片で FR-1 が効かなくなるほうが困るため。

### 6-9 キーの受け渡し（NFR-2 / NFR-7）

- **各機能は「自分が処理したかどうか」を返す。** 処理しなかった場合に何を起こすかは、キーを割り当てた側が決める。プラグインは既定の動作もほかのプラグインの動作も肩代わりしない。
- **insert モードで `<Tab>` に割り当てる用の入り口は、カーソルが項目の前置き（字下げ・マーカー・チェックボックス）にあるときだけ反応する。** 内容を打っている最中の `<Tab>` まで奪わないため。

### 6-10 設定（NFR-4）

- **対応する filetype は設定で足し引きする。既定は markdown だけ。** 一覧にない filetype のバッファでは、すべての機能が何もしない。
