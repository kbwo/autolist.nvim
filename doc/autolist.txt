1. INTRODUCTION                                         *autolist-introduction*

autolist maintains the shape of a list -- markers, numbering, indentation and
checkboxes -- so that writing the content is all that is left to do.

It never acts on its own. No key is mapped, no autocommand rewrites text, and
no line you did not touch is changed as a side effect. Everything below runs
because you invoked it.

Requires Neovim 0.9 or newer and nothing else.

==============================================================================
2. MAPPINGS                                                 *autolist-mappings*

autolist maps no keys. Choose them yourself.

Each entry point reports whether it acted, so a mapping can fall through to
whatever the key would otherwise do -- a default, or another plugin. The
expression helpers |autolist.cr()|, |autolist.o()|, |autolist.shift_o()|,
|autolist.tab()| and |autolist.shift_tab()| return a key sequence when autolist
wants the key and |nil| when it does not:
>lua
    vim.keymap.set('i', '<CR>', function()
      return require('autolist').cr() or '<CR>'
    end, { buffer = true, expr = true })
<
To keep another plugin that also owns the key, chain the calls:
>lua
    vim.keymap.set('i', '<CR>', function()
      return require('autolist').cr()
        or require('other-plugin').cr()
        or '<CR>'
    end, { buffer = true, expr = true })
<
The helpers work by returning a |<Cmd>| sequence, because an |:map-<expr>|
mapping is not allowed to change the buffer itself.

==============================================================================
3. COMMANDS                                                 *autolist-commands*

                                                            *:AutolistRenumber*
:AutolistRenumber
        Make the numbers of the list block around the cursor consecutive.
        See |autolist-renumbering|.

                                                              *:AutolistIndent*
:AutolistIndent
        Move the item under the cursor one level in, taking its continuation
        lines and nested items with it, and renumber the block.
        See |autolist-indenting|.

                                                              *:AutolistDedent*
:AutolistDedent
        The same, one level out.

                                                      *:AutolistToggleCheckbox*
:[range]AutolistToggleCheckbox
        Flip `[ ]` and `[x]` on the current line, or on every line of [range].
        Items without a checkbox are left alone.

                                                   *:AutolistCycleMarkersBlock*
:AutolistCycleMarkersBlock[!]
        Change every item of the block, at every level, to the next marker
        style in `cycle`. With [!], to the previous one.
        See |autolist-marker-styles|.

                                                *:AutolistCycleMarkersSiblings*
:AutolistCycleMarkersSiblings[!]
        Change only the run of siblings the cursor is in, leaving its parent
        and its nested items as they are. With [!], to the previous style.
        See |autolist-marker-styles|.

                                                            *:AutolistMakeList*
:[range]AutolistMakeList
        Give the plain lines of [range] a marker, turning notes written with
        nothing but indentation into a list. See |autolist-make-list|.

4. LUA API                                                       *autolist-api*

Every function returns `true` when it changed the buffer and `false` when it
decided not to act.

autolist.setup({opts})                                       *autolist.setup()*
        Override the defaults. Optional: the defaults already work for
        markdown. See |autolist-configuration|.

autolist.newline()                                         *autolist.newline()*
        Break the current list item and start the next one, or leave the list
        when the item is empty. See |autolist-newline|.

autolist.open_below()                                   *autolist.open_below()*
autolist.open_above()                                   *autolist.open_above()*
        Add an item on the line below or above the one under the cursor, the
        way `o` and `O` add a line, leaving the current line whole.
        See |autolist-open|.

        Insert mode is not started here; |autolist.o()| is the entry point
        that does it, for a key that is expected to end there.

autolist.indent()                                           *autolist.indent()*
autolist.dedent()                                           *autolist.dedent()*
        Move the item under the cursor one level and renumber the block.

autolist.renumber()                                       *autolist.renumber()*
        Renumber the list block around the cursor.

autolist.toggle_checkbox([{lnum}])                 *autolist.toggle_checkbox()*
        Flip the checkbox on {lnum}, or on the cursor line.

autolist.cycle_markers_block([{opts}])         *autolist.cycle_markers_block()*
autolist.cycle_markers_siblings([{opts}])   *autolist.cycle_markers_siblings()*
        Switch the block, or only the siblings at the cursor, to the next
        marker style. Pass `{ reverse = true }` for the previous one.
        See |autolist-marker-styles|.

autolist.make_list([{first}[, {last}]])                  *autolist.make_list()*
        Turn the plain lines between {first} and {last} into list items,
        keeping the indentation they already have. Defaults to the cursor
        line. See |autolist-make-list|.

autolist.at_item_prefix()                           *autolist.at_item_prefix()*
        Whether the cursor is in the leading part of a list item -- its
        indentation, marker or checkbox -- rather than in the content.

        This is the condition |autolist.tab()| applies internally, exposed for
        callers that cannot use an expression mapping. Routing `<Tab>` through
        another plugin's mapping table is the usual reason:
>lua
        ['<Tab>'] = cmp.mapping(function(fallback)
          local autolist = require('autolist')
          if cmp.visible() then
            cmp.select_next_item()
          elseif autolist.at_item_prefix() and autolist.indent() then
            return
          else
            fallback()
          end
        end, { 'i' }),
<
autolist.cr()                                                   *autolist.cr()*
        For an insert-mode |:map-<expr>| mapping: a key sequence that runs
        |autolist.newline()|, or |nil| when the cursor is not on a list item.

autolist.o()                                                     *autolist.o()*
autolist.shift_o()                                         *autolist.shift_o()*
        For a normal-mode |:map-<expr>| mapping on `o` and `O`: a key sequence
        that runs |autolist.open_below()| or |autolist.open_above()| and then
        starts insert mode at the end of the new item, or |nil| when the cursor
        is not on a list item.
>lua
        vim.keymap.set('n', 'o', function()
          return require('autolist').o() or 'o'
        end, { buffer = true, expr = true })
<
autolist.tab()                                                 *autolist.tab()*
autolist.shift_tab()                                     *autolist.shift_tab()*
        For an insert-mode |:map-<expr>| mapping: a key sequence that runs
        |autolist.indent()| or |autolist.dedent()|, or |nil|.

        These return |nil| unless the cursor is in the leading part of the item
        -- its indentation, marker or checkbox. Pressing the key while typing
        the content inserts a tab as usual.

==============================================================================
5. CONFIGURATION                                       *autolist-configuration*

Defaults:
>lua
    require('autolist').setup({
      filetypes = {
        markdown = {
          cycle = { '-', '- [ ]', '*', '1.', '1)', 'a)', 'I.' },
          checkbox = { checked = 'x', unchecked = ' ' },
          blockquote = true,
          code_blocks = true,
        },
      },
    })
<
filetypes                                            *autolist-opt-filetypes*
        Which filetypes autolist acts on. Add an entry to enable another one;
        it inherits the same per-filetype defaults. Set an entry to `false` to
        disable it. In a buffer of any other filetype every entry point does
        nothing and reports `false`.
>lua
        require('autolist').setup({
          filetypes = {
            text = {},
            markdown = { cycle = { '-', '1.' } },
          },
        })
<
cycle                                                     *autolist-opt-cycle*
        The order the marker styles are cycled through. Each entry is written
        the way it appears in the buffer, so `'1.'` and `'1)'` are different
        styles, and `'a)'` and `'I.'` set both the kind of numbering and its
        letter case.

        An entry may carry a checkbox, which makes having one part of the
        style: `'- [ ]'` is a different style from `'-'`, and cycling between
        them adds and removes the box. See |autolist-marker-styles|.

checkbox                                               *autolist-opt-checkbox*
        The characters written between the brackets. Reading is not affected:
        `[X]` is understood as checked whatever `checked` is set to.

blockquote                                           *autolist-opt-blockquote*
        Treat a leading `>` as part of the item prefix, so that lists inside a
        blockquote work like any other list and keep their quote markers.

code_blocks                                         *autolist-opt-code_blocks*
        Recognise fenced and indented code blocks and stay out of them.

Indentation is not configured here. 'shiftwidth', 'tabstop' and 'expandtab' are
read from the buffer being edited, so autolist writes indentation the same way
you do.

6. BEHAVIOUR                                               *autolist-behaviour*

Blocks and nesting                                             *autolist-block*

A list block is a run of consecutive lines that are list items or continuation
lines -- unmarked lines indented deeper than the item above, which are part of
that item's content. A block ends at a blank line, at a line that is neither of
those, at a change of blockquote depth, and at a code block.

Nesting is decided by comparing indentation, not by counting it: an item
indented further than the one above is its child, whatever the difference. Two-
and four-space indentation, and tabs mixed with spaces, all work.

Everything that renumbers works on one block, and counts each level of it
independently.

Continuing a list                                            *autolist-newline*

|autolist.newline()| starts the next item with the same indentation, the same
marker and the same delimiter, counting an ordered marker up. Breaking in the
middle of an item moves the rest of the line into the new one.

A checkbox is carried over but always starts unchecked, however the item above
was left.

A list written entirely with one repeated number (`1.` `1.` `1.`, which
markdown renders as a sequence anyway) goes on repeating that number.

On a continuation line, and with the cursor before the marker, it reports
`false` and leaves the key to you.

Adding a line above or below                                    *autolist-open*

|autolist.open_below()| and |autolist.open_above()| put a new item on the next
or the previous line, so that adding one does not mean going to the end of the
item you are on first. The line under the cursor is left whole, and where the
cursor sits within it makes no difference -- unlike a newline, nothing is cut
at that point.

The marker is built exactly as it is for a newline: same indentation, same
delimiter, an unchecked checkbox where the item has one, quote markers kept.
An item added below counts on from the current one; an item added above takes
over its place in the list, and with it its number.
>
    - apple|          →  o  →   - apple
                                - |

    2. apple|         →  O  →   2. |
                                2. apple
<
The items further down keep the numbers they had, which is the state
continuing a list on a newline leaves behind as well. |:AutolistRenumber|
makes them consecutive when you want them to be.

An item with no content gets a new item like any other: adding a line is not
how a list is left (that is |autolist-empty|), and clearing the line you are
standing on is not what the key was pressed for.

Leaving a list                                                 *autolist-empty*

|autolist.newline()| on an item with no content clears the item instead, so
that ending a list does not mean deleting the marker by hand. An item holding
nothing but a checkbox counts as empty. Inside a blockquote the quote markers
stay, because the text is still quoted.

Renumbering                                              *autolist-renumbering*

|:AutolistRenumber| runs only when you ask. Nothing watches the buffer.

There is no line limit: how far it reaches is decided by the block boundary
alone. Each level counts independently, and a level keeps the number it starts
from -- a list beginning at `3.` becomes `3. 4. 5.`, not `1. 2. 3.`.

Unordered items are not touched. Letters (`a) b) c)`) and Roman numerals
(`I. II. III.`) are counted as sequences.

A list written entirely with one repeated number is deliberate and is left
as it is.

Where items differ in style within one level, each keeps its own kind of
number and its own delimiter; only the order is made consecutive. Changing the
style is |:AutolistCycleMarkersBlock|' job.

Indenting                                                  *autolist-indenting*

|:AutolistIndent| moves the item together with its continuation lines and
nested items, then renumbers the block, so |:AutolistRenumber| is not needed
afterwards.

The new depth matches the children the previous sibling already has, so the
item joins an existing nested list rather than inventing a width for it. When
there are none, it moves in by 'shiftwidth'.

An item indented next to existing siblings continues their numbering. An item
that ends up alone at a level it just created starts that level from the
beginning.

The first item of a level cannot be indented -- there is nothing to nest it
under -- and a top-level item cannot be dedented. Both report `false`.

Marker styles                                          *autolist-marker-styles*

A style is the marker together with whether the item carries a checkbox. The
tick inside the box is not part of it: that is the writer's record of what is
done, not a matter of appearance.

Two commands move items to the next style in `cycle`, differing only in what
they take with them, because a nested list often wants a different marker per
level:

|:AutolistCycleMarkersBlock|     every item of the block, at every level
|:AutolistCycleMarkersSiblings|  only the run the cursor is in; its parent and
                                 its nested items are untouched

Either way, the style moved on from is the one the first item of the target
wears, and every item of the target ends up on the same next style. Both walk
the cycle backwards when given [!], so a step too far comes straight back, and
both wrap around at the ends. A style that is not in `cycle` lands on the start
of it whichever way you are going. When the result is ordered, each level is
numbered from the beginning.
>
    - 親                            - 親
        - 子     →  siblings  →         1. 子
        - 子                            2. 子
    - 親                            - 親
<
Where the next style has a checkbox, items without one gain an unchecked box
and items that already have one keep their tick. Where it has none, the box is
removed, so a full turn through the cycle brings the list back as it was.
>
    - 買い物                        - [ ] 買い物
    - 洗濯          →  cycle  →     - [ ] 洗濯
<

Turning plain text into a list                             *autolist-make-list*

Notes are often written with nothing but indentation for structure:
>
    ccmanager
        write a skill for the settings
        let Space delete a worktree
<
|:AutolistMakeList| gives those lines a marker. The indentation is left exactly
as it was and the marker goes after it, so the nesting the text already had
becomes the nesting of the list -- tabs and spaces alike.
>
    - ccmanager
        - write a skill for the settings
        - let Space delete a worktree
<
It marks the lines of the range you give it and nothing else. It does not look
for where the text starts and ends, because prose has no reliable boundary and
guessing wrong would rewrite lines you never pointed at.

Within the range it leaves alone: lines that are already items, blank lines,
thematic breaks, and anything inside a code block. Blockquote markers are kept.

The marker is the first entry of `cycle`, so there is no second setting to keep
in step. For any other style, run |:AutolistCycleMarkersBlock| afterwards. If
that first entry is an ordered marker, each level is numbered from the start.

Lines that are not lists                                        *autolist-code*

Things that only look like markers are left alone: fenced code blocks, indented
code blocks, emphasis such as `*bold*`, thematic breaks such as `---` and
`***`, and a `1.` appearing mid-sentence.

An indented code block is taken to be a line indented four columns or more that
follows a blank line and is not inside a list -- inside a list, deep
indentation is a continuation line or a nested item. Unlike CommonMark, an
indented first line of a buffer does not open one, so that a file holding only
a nested fragment of a list still works.

7. LIMITS                                                     *autolist-limits*

A single letter can be read either as a letter or as a Roman numeral: `i.` is
both "the ninth letter" and "one". autolist settles it from the siblings when
one of them is unambiguous (`ii.` makes the level Roman, `b.` makes it
alphabetic), and otherwise by case -- uppercase is Roman, lowercase is
alphabetic. A lone `c)` meant as the third letter is therefore read as the
third letter, but a lone `C.` is read as one hundred.

Alphabetic markers are runs of letters of one case, so `ab)` is a marker and
`Ab)` is not.

Blockquotes of different depths are separate blocks; numbering does not run
across them.

A count in front of a key mapped through |autolist.o()| or |autolist.shift_o()|
is not applied: `3o` on a list item adds one item, not three. The mapping
consumes the count. On a line autolist does not act on, the key falls through
with its count intact.

The specification these rules come from, including why each was decided this
way, is in `docs/requirements.md` (Japanese).
